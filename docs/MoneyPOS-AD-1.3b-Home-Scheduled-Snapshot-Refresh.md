# AD-1.3b HOME 定时日快照刷新

## 已确认策略

采用定时刷新而非 TRADE 订单事务事件。HOME 日快照还依赖库存估值与新增会员数，二者并不
只由订单结算/退款改变；定时重算能以较小边界覆盖这些输入，避免把 HOME 读模型写入耦合进
TRADE 事务。

## 实施

- 应用发出 `ApplicationReadyEvent` 后立即执行一次“补偿前七日缺失记录 + 刷新当天”。
- 此后每五分钟使用同一流程刷新；`GET /home/count` 和 `DecisionEngine` 的仪表盘方法只读
  HOME 快照，不再调用任何写命令。
- 任务使用 `AtomicBoolean` 拒绝重叠执行。命令先完成跨所有者的只读组装，再在独立短事务中
  原子写入；任一失败都记录错误日志、释放闸门且不删除已有日快照，因此保留上次有效数据。
- 后台线程没有 HTTP 请求上下文时，多租户拦截器使用既有配置的默认租户，而不是断言失败。
  这也使已有后台任务拥有确定的默认租户语义。
- 若当天快照因启动或调度失败而尚不存在，读取端返回零值 HOME 视图并保持 GET 可用，等待下次
  调度恢复；不会由 GET 重新获得写权限。

## 验收

HOME 集成测试验证 GET 在删除当天快照后不写入、无 HTTP 租户上下文的刷新可创建快照、定时命令
可覆盖当天值并保持 `member_recharge`、补偿窗口不变。独立单元测试验证重叠触发只运行一次，
失败后闸门会释放以允许下一轮恢复。
