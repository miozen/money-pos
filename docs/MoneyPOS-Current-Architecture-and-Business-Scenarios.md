# MoneyPOS 当前架构与业务场景总览

> 依据 2026-09-22 `dev` 源码、Flyway、回归和已完成环境验收整理。它描述**当前事实**；历史阶段文档中的“下一任务”仅保留当时决策，不是当前待办。

## 运行与边界

MoneyPOS 是单机桌面收银系统：Electron 前端启动 Java 17 / Spring Boot 2.7 后端；Windows 打包版使用嵌入式 MariaDB、Flyway 和本地数据目录。后端是一个 Boot 应用，Maven 保持 `api`、`system`、`biz` 三个物理模块；GMS、UMS、TRADE、FIN、HOME、SYS 是 `biz` 内的逻辑 Feature，并非可独立部署服务。

| Feature | 所有数据/职责 | 面向其他 Feature 的方式 |
| --- | --- | --- |
| GMS | 商品、品牌、分类、套餐、库存、入出库单、库存流水、库存分析 | 商品/库存/品牌/分类快照或命令契约 |
| UMS | 会员档案、等级、余额、会员券、充值凭证、会员流水 | 会员校验、定价权益、资产、券钱包和画像快照/命令 |
| TRADE | POS、订单、明细、支付、退款、订单日志及交易侧报表原子查询 | 订单、支付、经营读模型快照 |
| FIN | 财务看板、交接班、经营/营销/风险分析展示 | 消费 TRADE/GMS/UMS/SYS 的只读快照，不直读其 Entity/Mapper |
| HOME | 首页计数、趋势和每日经营快照 | 消费 TRADE/GMS/UMS 的读模型；自身拥有日快照写入 |
| SYS | 字典、策略、打印配置、地区、备份、文件/客显配置 | 提供配置和窄查询契约 |

架构门禁已确认 Controller 不直连 Mapper，Feature 不直连其他 Feature 的 Mapper/实现类，且共享 `com.money.entity`、兼容桥与通配符导入均为零。跨域协作均通过 API-neutral DTO、快照或命令接口；结算和退款仍在单数据库、本地 Spring 事务中完成。

## 核心交易闭环

### 1. POS 搜索、试算与结算

POS 通过 `/pos/goods`、`/pos/members` 和会员/券规则查询取得商品、会员和权益信息；商品可为普通商品或套餐，会员可使用余额及会员权益。`/pos/trial` 只计算价格、满减券、会员券和支付提示，不落订单。

`/pos/settleAccounts` 进入 TRADE 的单事务 `CheckoutOrchestrator`：

1. 以 `reqId` 检查既有订单，命中时恢复原结算结果，避免重复扣款；
2. 校验购物车、商品、会员、支付渠道/标签、余额支付资格和金额；
3. 用商品/会员快照计算成交价、手工优惠、满减券、会员券与应付金额，并规范化多笔支付与找零；
4. 写入订单和订单明细；
5. 调用 GMS 库存命令原子扣减普通商品或套餐配额及其子商品，写 `SALE_OUT` 库存单和 `SALE` 流水；
6. 调用 UMS 命令扣余额/券、核销会员券并记录资产流水；
7. 写支付记录和 JSON 订单审计日志，返回订单号、应付、实收、找零及优惠快照。

任一步抛出异常，Spring 事务回滚订单、库存、会员资产和支付写入。收银小票可由订单硬件打印入口调用，已完成实机打印验收。

### 2. 全额退款与部分退货

`/oms-order/return` 是整单退款，`/oms-order/returnGoods` 是按订单明细和数量的部分退货。两者先用 `reqId + 退款类型` 防重放，再校验订单仍可退款和明细归属。

- **整单**：订单金额、成本及优惠快照归零，状态写入 `REFUNDED`；所有明细返库，GMS 写 `RETURN` 库存单/流水；UMS 原路恢复余额、会员券和已用满减券；最后追加订单日志。
- **部分**：按成交单价和明细券额计算退款，明细以剩余数量原子守卫返库；订单累减销售额、成本、券额并写 `PARTIAL_REFUNDED`。若所有明细都退完，再升级为 `REFUNDED`。

当前业务只新写 `REFUNDED`。历史订单可保留 `RETURN`；二者都显示“已退单”，并在所有原本含全额退款的经营、支付、审计、商品及会员统计中等价处理。库存领域 `RETURN` 是独立的库存类型码，不等于订单历史状态。

## 商品、库存与会员

### 商品和库存（GMS）

商品、品牌、分类、套餐、会员等级价格矩阵通过 GMS 管理；支持分页增改删、Excel 导入导出、POS 搜索和品牌券策略配置。库存管理提供入库、盘点、出库；库存分析提供库存报表、周转预警、补货/滞销导出和库存流水。结算/退款只经 GMS 命令协作，TRADE 不直接写库存表。

### 会员与资产（UMS）

UMS 管理会员档案、等级、品牌等级矩阵、导入导出、沉睡/排行、余额和会员券。充值生成充值凭证和流水，可按凭证红冲。结算时 UMS 以原子 SQL 扣余额/券；退款时恢复相应资产并写可追溯流水。满减券规则、发券、卡包、FIFO 核销和退款恢复由 UMS 所有；TRADE 仅消费权益/钱包快照或资产命令。

## 查询、报表与运行能力

- **订单与打印**：`/oms-order/page`、详情、统计、退款、毛利审计和硬件打印由 TRADE 提供；订单详情组装会员档案、支付和日志快照。
- **FIN**：财务看板、渠道构成、利润排行、营销复盘、交接班及打印、风控、资产看板和每日瀑布报表。FIN 负责展示/组合，TRADE 负责订单金额、退款、支付和订单明细原子数据，GMS/UMS/SYS 分别提供品牌、会员资产和策略/名称快照。
- **HOME**：首页计数和趋势读取自 HOME 日快照与 TRADE 原子查询。后台在应用就绪及每五分钟刷新最近缺失日/当天快照；GET 不写数据。启动优化已冻结，此行为保持不变。
- **SYS/运行时**：字典为支付方式、订单状态和会员类型等提供显示值；Flyway 管理版本迁移（目前含 `REFUNDED` 字典迁移）。SYS 还提供打印配置、地区、备份恢复、文件上传、本地静态资源和客显设置。Electron 依赖 actuator health 创建窗口；嵌入式 MariaDB、Flyway、安全、多租户和支付字典校验均为保留能力。

## 当前验收、冻结项与操作约束

- 已验收：Java 17 Windows EXE、既有数据启动、health、收银窗口、收银小票打印；核心收银、整单/部分退款及隔离 MariaDB 自动回归。
- 条件验收：钱箱仅在实际启用时再测试；退款小票没有产品入口。
- 已冻结：启动优化和 ENV-1 剩余测量、SQLite 迁移、Maven Feature 物理拆分、Boot 3/Jakarta 升级，以及无证据的无效代码删除。
- 协作：只在 `dev` 上工作；每项改动完成本地提交后，由用户使用 SSH-over-443 推送并确认 `dev...origin/dev`。新增任务必须先说明业务边界、回归和是否影响既有数据。
