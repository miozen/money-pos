# GMS-OPT-2：手工报损原子库存守卫实施契约

## 目标

修复手工 `POST /gms/inventory/outbound` 的“先读库存、后无条件扣减”并发窗口。仅报损出库改为使用现有
`GmsGoodsMapper.deductStockAtomically(id, qty)` 的 `UPDATE ... WHERE stock >= qty` 原子守卫。

## 保持不变

- 路由、权限、单据号、主单/明细/流水表、财务成本公式和事务所有者不变；
- 入库的移动加权成本、盘点的实际数量校正不变；
- 手工报损继续只影响用户所选商品，不复用会穿透套餐子件的 `GmsGoodsStockService`；
- 不引入请求幂等键、不新增迁移、不改 TRADE 库存命令。

## 最小实现

1. `OUTBOUND` 在已完成参数计算后执行条件扣减；受影响行数为零即抛出原有“库存不足”语义，整张单据事务回滚。
2. 条件扣减成功后，在同一事务内重新读取该商品，以实际余额构造单据明细和库存流水的前后库存快照。
3. `INBOUND` 与 `CHECK` 保持原更新路径，避免扩大本切片的成本或盘点规则。

## 验收

- 库存刚好足够时报损成功，库存、单据明细和流水前后值一致；
- 库存不足（包括竞争导致条件更新失败）时不产生主单、明细或流水；
- 其余手工库存类型与公开接口保持兼容。
