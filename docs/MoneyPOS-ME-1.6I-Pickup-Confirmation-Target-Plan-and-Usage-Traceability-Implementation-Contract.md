# MoneyPOS ME-1.6I：提货确认、升级计划与权益使用可追溯性实施合同

> 状态：**I-A～I-D complete; ME-1.6I automated work closed**；确认日期：2026-10-10；适用分支：`dev`。
>
> 本合同记录已确认的下一轮权益调整，并授权按第 3 节顺序实施。ME-1.6H 的 Windows Electron/POS
> 手工验收仍是该阶段的关闭条件；它不阻断本合同已确认的后续实现，但不得被误报为已完成。

## 1. 事实基线

- QUANTITY 提货现在直接提交：列表内填写数量后即可调用实际提货，没有“预览后确认”的安全步骤。
- TARGET 计划有建立、进度、人工确认、退款复核与审计式取消能力。当前普通购物车只能选择一个计划，且后端
  拒绝含非计划品牌明细的 TARGET 结算；I-C 将替换这一限制。
- QUANTITY 提货已有 `OmsMemberQuantityPickup`/明细、`PICKUP_DEDUCT` 权益流水和自动“会员提货单”；
  AMOUNT 提货已有提货单、补差凭证和 `PICKUP_DEDUCT` 流水，但没有打印提货单；TARGET 正常销售已有
  `SALE_CONTRIBUTION` 进度流水，销售小票仍是普通订单小票。
- 权益工作台当前只显示权益余额/计划状态，传统会员资产流水也不查询 QUANTITY、AMOUNT 或 TARGET 的
  专用账本。因此“使用记录不存在”是展示缺口，不是上述业务记录均未持久化。

## 2. 冻结业务规则

### ME-1.6I-A：QUANTITY 提货预览与二次确认

1. 本次提货数量必须作为独立、清晰的操作列/提货清单，不与权益状态文字混排。
2. 操作固定为“编辑数量 → 预览提货 → 确认弹窗 → 确认提货”。修改商品或数量后，原预览立即失效。
3. 预览逐行展示商品、寄存总数、已提数、本次提货数和提货后剩余数；确认弹窗再次汇总这些信息。
4. 预览只能读，不可预扣；最终提交仍在既有原子事务内重新校验权益和实体库存。普通 POS 购物车继续
   完全隔离。

### ME-1.6I-B：TARGET 计划取消，不做物理删除

1. 不提供物理删除。计划、初始进度、销售贡献、补差和豁免均须保留审计链。
2. 新增 `CANCELLED` 终态和“取消计划”操作：仅 `IN_PROGRESS` 且除 `INITIAL_PROGRESS` 外没有销售贡献、
   补差或豁免流水的计划可取消。
3. 取消必须记录操作人、时间、原因和幂等请求号；取消后不得出现在 POS 可选计划中。
4. 有后续业务流水的计划拒绝取消，保留既有复核/人工处理路径，不得借取消反冲历史销售或等级。

### ME-1.6I-C：混合购物车按计划品牌贡献 TARGET 进度

1. 普通购物车可混合品牌，仍为一张普通订单和一次普通结算。订单可同时关联多个 TARGET 计划，但同一品牌
   最多关联一个计划；一个计划也只接收其自身品牌的商品贡献。
2. POS 在结算确认前，按会员、购物车品牌和计划状态默认勾选每个可贡献的进行中计划；收银员可逐计划关闭。
   只有收银员仍明确勾选的计划才可计入。无对应品牌商品、已取消、已确认、退款待复核或已达标待人工确认的
   计划不得显示为可选或继续贡献。
3. 同一会员同一品牌在一次结算中最多只能确认一个计划；不同品牌计划可同时确认。后端必须验证所选计划仍属
   于该会员、本单品牌且可贡献，绝不按创建时间等隐式规则猜测或自动补选。
4. 每个计划的贡献额为其品牌明细自身的实际成交净额。明细已有的会员券/商品优惠继续按明细事实扣减；满减券和
   整单优惠是订单级结算事实，不分摊至订单明细或 TARGET 计划，不得使用整单实收金额充当任何品牌的贡献。
5. 建立 TARGET 计划不改变会员当前品牌等级价；达到目标后仍必须人工确认，确认才切换到目标档位价格。TARGET
   补差是独立业务单据和进度来源，不是普通商品结算的自动价格差。
6. 前端明确展示每个默认勾选计划的“本单计入金额”和不计入商品；后端只以已持久化订单明细复算已确认计划
   的金额，不信任前端传入的贡献金额。
7. 关联销售退款仍只置 `REVIEW_REQUIRED`，不得自动降级或自动反冲历史等级。

### ME-1.6I-D：会员全景画像资产与权益变动流水、单据展示

会员全景画像必须能审计会员资产和权益的完整变动；库存流水继续是库存审计依据，不能被替代或复制为会员账本。

1. 会员全景画像的现有“资产变动流水”扩展为只读的“资产与权益变动流水”。它聚合原有余额/会员券流水、
   QUANTITY/AMOUNT 权益账本、TARGET 进度流水和 TRADE 业务单据；不得向 `ums_member_log` 伪造金额或券变动，
   也不得复制或替代 GMS 库存流水。
2. 每行至少展示时间、业务类型、资产/权益维度、变动值、变动前后值、单位（元、张、件或进度）、关联业务单号、
   单据类型、操作人、状态和摘要。不同单位不得混入同一“变动金额”含义。
3. QUANTITY 寄存办理、QUANTITY 提货、AMOUNT 权益办理/提货/补差、TARGET 贡献/补差/豁免/人工确认均须能追溯到
   其权威来源。普通余额/会员券流水继续保持原有显示与查询语义。
4. 读取聚合通过 `money-app-api` 的 Entity-free 契约完成；UMS 不得直接引用 TRADE 的 Entity、Mapper 或实现类。
   聚合读取不得产生业务写入、库存变更、权益变更或打印副作用。
5. QDP 是 QUANTITY 寄存办理的普通订单号，点击时必须打开普通订单详情。前端不得再通过 `RC`/`RE` 等单号前缀
   推断页面路由；记录应提供明确的单据类型/详情目标。历史 QDP 订单必须同样可打开。
6. QUANTITY 继续使用现有自动会员提货单，且在记录中可按提货单号查询/补看；不得因页面查询或重试重复打印。
   AMOUNT 提货补齐非销售“会员提货单”打印，沿用同一独立打印开关与非阻塞副作用语义，不开钱箱、不改变补差、
   库存或账本事务。TARGET 正常销售继续只打印普通销售小票，不产生第二张提货单。

## 9. I-C 后续已确认调整：整单优惠保持订单级语义

确认日期：2026-10-12。

1. `manualDiscountAmount` 继续是订单头级的直接减免，保留既有结算上限和退款语义；不新增商品行分摊字段、
   分摊快照或历史订单回填。
2. 满减券不属于本调整：其门槛、会员资产核销及“部分退不返、订单最终全退才返”的规则均保持不变。升级计划
   商品不参与或承担满减券。
3. TARGET 自动贡献和 POS 的“本单计入金额”均仅使用该计划品牌订单明细自身的净额（已有明细会员券/商品优惠
   已扣）；不得因满减券或整单优惠再按比例扣减。
4. 订单实付仍可能低于商品行金额合计；收款、退款总额和财务统计继续以订单头结算金额及既有退款规则为准。
   本调整不改变交易路由、订单字段、事务归属、满减券或退款实现。

## 10. I-C 后续已确认调整：收银员确认 TARGET 计划与支付区布局

确认日期：2026-10-12。

1. 混合收银工作站按购物车品牌加载可贡献的进行中 TARGET 计划，并默认勾选；收银员可以逐项关闭。不同品牌
   计划可同时保持勾选，一张普通订单可分别为这些计划写贡献；全部关闭则不写任何 TARGET 贡献。
2. 结算请求仅携带仍勾选的计划 ID。TRADE 在同一既有结算事务内复核计划是否仍属该会员、本单品牌且可计入，
   并拒绝同一品牌同时选择多个计划、失效计划或非本单品牌计划；不再由后端自动计入或补选。
3. 整单优惠和“免收会员券”控件置于组合支付明细之后；保留一行一种支付方式及现有输入/渠道按钮布局，仅收紧
   纵向间距并使用视口约束的主体高度。默认窗口高度内无需滚动即可看见和操作全部支付/优惠控件，且不能覆盖
   固定的“实收总计”及确认收款区域。左侧升级计划可局部滚动；计划行仅显示“计入 + 计划
   名称 + 本单计入金额”。两项结算规则和金额计算不变。
4. 未新增迁移或历史数据处理；TARGET 的退款复核、满减券、订单级整单优惠和普通订单结算事务均保持既有语义。
