## 1. 事实基线

- QUANTITY 提货现在直接提交：列表内填写数量后即可调用实际提货，没有“预览后确认”的安全步骤。
- TARGET 计划只有建立与既有进度/确认/复核能力；没有取消或物理删除 API。普通购物车只有一个品牌时才
  可选择该品牌的计划；后端也拒绝含非计划品牌明细的 TARGET 结算。
- QUANTITY 提货已有 `OmsMemberQuantityPickup`/明细、`PICKUP_DEDUCT` 权益流水和自动“会员提货单”；
  AMOUNT 提货已有提货单、补差凭证和 `PICKUP_DEDUCT` 流水，但没有打印提货单；TARGET 正常销售已有
  `SALE_CONTRIBUTION` 进度流水，销售小票仍是普通订单小票。
- 权益工作台当前只显示权益余额/计划状态，传统会员资产流水也不查询 QUANTITY、AMOUNT 或 TARGET 的
  专用账本。因此“使用记录不存在”是展示缺口，不是上述业务记录均未持久化。

## 2. 冻结业务规则

### ME-1.6I-A：QUANTITY 提货预览与二次确认

1. 本次提货数量必须作为独立、清晰的操作列/提货清单，不与权益状态文字混排。
2. 操作固定为“编辑数量 → 预览提货 → 确认弹窗 → 确认提货”。修改商品或数量后，原预览立即失效。
3. 预览逐行展示商品、寄存总数、已提数、本次提货数和提货后剩余数；确认弹窗再次汇总这些信息。
4. 预览只能读，不可预扣；最终提交仍在既有原子事务内重新校验权益和实体库存。普通 POS 购物车继续
   完全隔离。

### ME-1.6I-B：TARGET 计划取消，不做物理删除

1. 不提供物理删除。计划、初始进度、销售贡献、补差和豁免均须保留审计链。
2. 新增 `CANCELLED` 终态和“取消计划”操作：仅 `IN_PROGRESS` 且除 `INITIAL_PROGRESS` 外没有销售贡献、
   补差或豁免流水的计划可取消。
3. 取消必须记录操作人、时间、原因和幂等请求号；取消后不得出现在 POS 可选计划中。
4. 有后续业务流水的计划拒绝取消，保留既有复核/人工处理路径，不得借取消反冲历史销售或等级。

### ME-1.6I-C：混合购物车按计划品牌贡献 TARGET 进度

1. 普通购物车可混合品牌，仍为一张普通订单和一次普通结算；一次订单最多选择一个 TARGET 计划。
2. 选中计划后，只计算该计划品牌的合格订单明细；其他品牌商品正常销售、对该计划贡献为零。
3. 贡献额为计划品牌明细的实际成交净额。会员券、商品优惠和整单优惠必须沿既有结算结果分摊至订单明细后
   再汇总；不得使用整单实收金额充当该品牌贡献。
4. 购物车没有计划品牌商品时不得选择该计划。前端在结算确认前明确展示“本单计入计划金额”和“不计入
   商品”的边界；后端仅以已持久化订单明细复算，绝不信任前端传入贡献金额。
5. 关联销售退款仍只置 `REVIEW_REQUIRED`，不得自动降级或自动反冲历史等级。

### ME-1.6I-D：权益使用记录与单据展示（待确认提案）

用户提出“权益使用是否应有单据、资产流水是否应体现”的观察；以下为待确认提案，尚不授权实施：

1. 权益工作台新增“使用记录/业务单据”只读入口，统一展示 QUANTITY 提货、AMOUNT 提货与补差凭证、
   TARGET 进度贡献/补差/豁免/人工确认；每行显示时间、类型、业务单号、变动前后值、操作人、状态和来源。
2. QUANTITY 继续使用现有自动会员提货单，且在记录中可按提货单号查询/补看；不得因页面重试重复打印。
3. AMOUNT 提货补齐非销售“会员提货单”打印，沿用同一独立打印开关与非阻塞副作用语义，不开钱箱、不改变
   补差、库存或账本事务。
4. TARGET 正常销售继续只打印普通销售小票，不产生第二张提货单；使用记录和普通订单详情须可显示该订单
   已计入的计划及贡献金额。TARGET 补差/豁免/人工确认至少须在使用记录中有可追溯凭证，不擅自新增收银小票。

## 3. 实施顺序与验收

1. I-A：先增加 QUANTITY 预览读契约、确认交互和最终重校验回归。
2. I-B：再增加 TARGET 取消状态、审计命令与拒绝有业务流水计划的回归。
3. I-C：最后调整普通 Checkout 后的按明细贡献归集，覆盖混单、整单优惠分摊、单计划限制、退款复核和普通
   Checkout 不变。
4. I-D：基于既有业务单与权益账本提供只读历史，补 AMOUNT 提货打印，并验证 QUANTITY 不重复打印、TARGET
   不产生第二张销售小票。
