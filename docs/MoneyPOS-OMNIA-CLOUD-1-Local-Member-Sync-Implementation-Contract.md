# MoneyPOS OMNIA-CLOUD-1 本地会员同步基础实施契约

> 状态：已确认，按本切片实施；确认日期：2026-10-16；适用分支：`dev`。

## 1. 目标

为独立 Omnia Cloud 查询中心建立 MoneyPOS 本地、可靠、最终一致的会员只读快照基础。
MariaDB 继续是唯一业务权威；本切片不建立 Cloudflare 项目、不配置网络、账号、密钥或生产部署，也不向任何外部服务发送会员数据。

## 2. 范围

1. 新建 UMS 自有的会员云查询快照 DTO、组装器和合并式本地 Outbox。
2. 在已拥有会员资料、资产、券钱包、权益和合并状态的 UMS 写事务内标记受影响会员。
3. 新建本地调度/投递抽象、失败退避和可测试的禁用默认实现；真实 HTTPS Worker 客户端留给后续独立切片。
4. 新建 Flyway 表，不修改既有表、公开路由、收银/退款/库存事务所有者、金额公式或历史数据。

## 3. 快照边界

快照只包含会员编号/状态、姓名、卡号、手机号的本地规范化检索材料、余额、金额券额、未使用券按规则汇总、品牌等级以及 QUANTITY/AMOUNT/TARGET 当前权益。
不包含地址、备注、操作员、订单、支付、充值/权益流水、完整资产历史或商品成本。TARGET 剩余额度固定为 `max(targetAmount-progressAmount, 0)`；所有权益均采用账本当前剩余字段与计划快照字段。

## 4. Outbox 与事务

`cloud_member_sync_outbox` 以 `(tenant_id, member_id)` 唯一，保存最新 `UPSERT` 或 `TOMBSTONE`、单调版本、状态、失败/退避与发送审计字段。同一会员的连续变更合并为一条最新待发记录。

标记写入必须参与原 UMS Spring 事务；远程调用绝不在收银、退款、充值、合并或权益交易事务内执行。业务回滚时 Outbox 同步回滚。删除/合并来源写 `TOMBSTONE`；合并目标写 `UPSERT`。

## 5. 接入边界

- 档案新增、修改、删除、导入、发券；
- 余额、券额、券包充值/撤销、结算与退款；
- QUANTITY、AMOUNT、TARGET 的授予、提货、退款恢复、计划创建、进度、确认、复核和取消；
- 人工合并的来源与目标。

跨 Feature 仍只可通过 `money-app-api` 的 Entity-free 契约；不允许 Cloud 同步代码引用 TRADE/GMS Entity、Mapper 或实现类。

## 6. 验收

专项测试须证明：快照字段及 TARGET 剩余计算正确；事务回滚不遗留 Outbox；重复标记只保留一条最新记录；合并/删除写正确 tombstone；投递失败退避、成功确认和重复投递均可安全重试。每个完成切片还须运行受影响回归、打包、两项架构扫描和差异检查。

## 7. 后续切片（非本切片）

1. 经单独授权后建立 Worker/D1 同步接收端与请求签名；
2. 经单独授权后部署独立 Vue 查询端与 Telegram Webhook；
3. 再以独立 GMS 切片处理商品和库存投影。

## 8. 完成事实（2026-10-16）

`V1.0.23` 已新增 UMS 自有 `cloud_member_sync_outbox`。档案、导入/发券、充值/红冲、POS 结算与退款、余额凭证、三类权益账本和人工合并均在既有本地事务中标记最新会员投影；合并来源使用 `TOMBSTONE`，目标使用 `UPSERT`。快照组装器只读取 UMS 当前状态，未增加外部 HTTP 调用或公开路由。调度器默认不启用；没有经单独授权的 Worker 发布器时不会向任何网络服务发送数据。

隔离 `money_pos_test` 的新 Outbox 专项（1 项）、充值（1 项）、权益账本（6 项）和会员删除/合并（6 项）回归通过；完整 Maven 回归产生 85 份 Surefire 报告且 0 failure/error。`mvn -q package -DskipTests`、两项架构门禁和 `git diff --check` 通过。
