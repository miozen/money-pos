# MoneyPOS POS-11 混合收银会员券不足提示布局实施契约

> 状态：已接受，实施中；确认日期：2026-10-26；适用分支：`dev`。

## 目标与边界

只改善混合收银工作站内“免收会员券”开关与既有会员券不足提示的可见性。不得改变弹窗尺寸、试算、会员券扣减、免券开关语义、收款禁用条件、接口、后端或数据库。

## 冻结决定

- 既有提示文案、提示条件和红色闪烁样式保持不变。
- 提示从开关下方的独立第二行移至“免收会员券”标签与“否/是”开关之间，同一横行显示。
- 开关始终位于该行最右侧；提示存在或隐藏均不改变开关位置。
- 中间空白由弹性占位填充；标签和开关不可压缩。工作站保持既有 `900px` 宽度，不新增滚动区、浮层或绝对定位。
- 会员券不足仍以 `!isWaiveCoupon && currentMember.coupon < theoreticalCouponUsed` 判断；`isSubmitDisabled` 和 `handleDiscountChange` 不作任何改动。

## 验收

1. 会员券不足时，完整既有提示词与开关在同一行可见，开关不被遮挡。
2. 开启免收或会员券充足时，提示隐藏，但开关仍保持同一最右位置。
3. 混合收银的试算、确认收款禁用、会员券扣减与其他支付方式行为不变。
4. 前端构建、后端打包、架构门禁与差异检查通过；随后在 POS 结算窗口完成一次人工验收。

## 本地完成事实

- 仅修改 `CheckoutModal.vue` 的既有会员券不足提示容器：提示与开关改为单一 flex 行，开关为不可压缩的最右元素，提示隐藏时由弹性空白占位。
- 未改动不足条件、提示文字、开关绑定、试算、支付重算或提交禁用条件。
- 已通过 `money-pos-web` 的 `npm run build`、`mvn -q package -DskipTests`、两项架构门禁和 `git diff --check`。前端构建有既有的 CSS/包体积警告但成功完成；提交和 POS 人工验收待执行。
