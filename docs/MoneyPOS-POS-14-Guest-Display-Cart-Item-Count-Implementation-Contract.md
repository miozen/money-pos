# MoneyPOS POS-14 副屏购物篮总件数实施契约

> 状态：本地实施与自动校验完成，待副屏运行时验收；确认日期：2026-10-26；适用分支：`dev`。

## 目标与边界

让顾客副屏在收银清单状态明确显示购物篮总件数。当前“清单 (N)”实际是购物车行数/商品种类数，不能表达总件数。

不改变 POS 购物车、扫码、数量、价格、试算、结算、会员、库存、WebSocket 协议、后端或数据库。

## 冻结决定

- 副屏左上蓝色标题由“清单 (N)”改为“购物清单 · 共 X 件”。
- `X` 使用副屏已接收的每行 `qty` 求和，与 POS 主界面“共 X 件”口径一致。
- 不额外显示商品种类数，以免标题栏重复和顾客误解；会员标签继续保持右侧。

## 验收

1. 多种商品与同种商品多件时，副屏显示所有行数量之和。
2. 扫码、增减数量、删除、清空、挂单恢复和结算状态切换后，副屏件数随现有同步即时更新。
3. 不新增 WebSocket 字段，不改变主 POS、后端或数据持久化。

## 实施与验证事实

- 实施仅修改 `money-pos-web/src/views/display/guest/index.vue`：以现有 `realCart` 与 `getQty` 计算 `totalItemCount`，并替换左上标题文案。
- 未修改 POS 到副屏的同步消息、后端接口、数据库、价格或购物车逻辑。
- 已通过：`money-pos-web` 的 `npm run build`、`mvn -q package -DskipTests`、`scripts/test-architecture-scan.sh`、`scripts/architecture-scan.sh --check-new` 与 `git diff --check`。
- 前端构建仍会报告既有的 Browserslist、CSS 解析和大体积 chunk 提示，但构建成功；这些提示并非本次改动新增。

## 待副屏运行时验收

使用两种商品、其中一种数量大于 1 的购物车确认总数为各行数量之和；再确认扫码、改数量、删除、清空、挂单恢复和结算状态变化后标题随现有副屏同步更新。
