# MoneyPOS 产品优化需求台账与初步实施方案

> 记录日期：2026-09-22。本文只登记需求、源码现状、风险和分期建议；不构成已授权的代码改动。

## 目标

在不破坏现有收银、退款、库存和会员资产事务的前提下，优先提升门店操作安全性、收银台可用性和管理端信息密度；随后再评估会员外部查询与会员产品能力。

## 已确认的设计边界

1. **库存拦截不能只做前端。** 前端提示可改善体验，但库存扣减必须继续由 GMS 原子命令在 TRADE 的结算事务内兜底，避免并发超卖。
2. **收银员切换是身份切换。** 它必须重用账号认证和权限体系，订单操作人必须由后端认证上下文决定，不能把收银员姓名作为前端可编辑字段提交。
3. **钱箱是硬件动作。** 需要用订单详情中的已持久化找零金额判断，不能用界面试算值；打印、补打、交班打印和人工开箱必须区分语义。
4. **关闭确认需要在 Electron 主进程处理。** 仅在 Vue 页面拦截不能覆盖窗口标题栏、任务栏和系统关机路径；确认后再终止后端，取消则保持窗口和收银状态。
5. **Cloudflare 不得直连门店数据库。** 同步应是门店端向外推送，Worker 只接收经签名/认证的最小数据；公开网站不得暴露余额、券、交易明细、手机号全文或可猜测的会员标识。
6. **报表重组先不改指标。** 当前 FIN/HOME 的读取边界和交易公式已完成架构收敛，信息架构改造必须先证明“同一数据、不同呈现”，再讨论新指标或计算口径。

## 推荐实施顺序

### 阶段 A：安全与防误操作（建议最先授权）

1. UX-1 复现实机“后台无密码”路径，审计初始账号、生产构建变量、令牌留存与后台入口权限。
2. 设计并实施首次管理员密码设置/强制改密或修复实际绕过点；补登录、改密、登出和初始化回归。
3. UX-2 实施桌面关闭确认，并覆盖空购物车、非空购物车、已挂单和确认退出四种场景。

验收：桌面安装包中无法不经认证进入管理功能；取消关闭不丢失界面状态；确认关闭后 Java 子进程正常结束。

### 阶段 B：收银台即时反馈（建议第二批）

1. UX-3/UX-4 统一库存状态模型：可售、库存为零、购物车数量超库存、套餐配额不足。
2. 扫码或选择零库存商品时显示非阻塞、可关闭的行内提示；购物车对应行高亮并提供“补货”按钮/快捷操作。
3. 数量变化和进入结算前显示聚合的阻断原因；正式结算继续依赖现有后端原子校验。
4. 回归普通商品、套餐、并发库存变化、补货后重试和退款返库。

验收：顶部菜单始终可点击；提示可以立即关闭；收银员无需等待提示超时即可转到补货；任何路径都不能绕过库存扣减守卫。

### 阶段 C：人员与硬件语义（建议第三批）

1. UX-6 设计锁屏切换收银员：二次登录、权限刷新、审计归属、非空购物车的继续/挂单/清空决策。
2. UX-7 盘点“结账自动打印、订单补打、交班打印、人工开箱”四类调用，再把开箱条件收敛至正确的订单已持久化找零结果。
3. 在实际打印机/钱箱上验证：现金有找零、现金无找零、扫码、余额、混合支付、补打和手动开箱。

### 阶段 D：产品发现与管理端整理

1. UX-5 召开/记录会员产品仓库发现：目标用户、商品类型、价格/库存/有效期、是否可在 POS 销售、是否关联会员等级/券/余额、退款规则及报表口径。
2. UX-9 盘点现有页面与指标，按“今日经营、收银交班、商品库存、会员经营、风险与审计”形成候选导航；标记保留、合并、下沉和废弃候选，但不删除任何能力。
3. 对每个被批准的业务领域分别设计路由、权限、数据所有者、回归和迁移计划。

### 阶段 E：Cloudflare 会员查询（独立项目）

1. 明确网站使用者（店员、会员本人或总部）、查询键（手机号后四位/会员号/扫码）和允许展示字段。
2. 设计数据生命周期：本地变更 outbox、重试/幂等、删除或脱敏同步、断网补偿、可观测审计。
3. 设计 Worker API 与认证：门店上传凭证、网站身份认证、RBAC、速率限制、机器人防护、查询审计和密钥轮换。
4. 选择 Cloudflare 存储与部署边界后，再建立独立网站仓库或经授权在本仓库新增站点；先用脱敏测试数据完成端到端验证。

## 在实施前需要确认的产品决策

1. “后台没有密码”是首次安装的默认账号问题、打开后台页无需再次验证，还是已经登录的收银员可以直接进入管理页？请提供复现步骤或截图即可定位。
2. 关闭确认中，若购物车有商品，是否允许“确认退出并丢弃购物车”，还是必须先挂单/清空？
3. 零库存商品期望“禁止加入购物车”，还是“允许加入以便快速补货，但禁止结算”？本文暂按后者规划，因为现有流程已采用后端结算拦截。
4. 钱箱是否应当在现金支付但**无需找零**时打开？本文按“仅实际找零自动打开，人工开箱另设权限”作为默认建议。
5. “会员产品仓库”具体想管理什么类型的产品，以及是否涉及库存、核销、支付和退款？
6. Cloudflare 网站的访问对象和会员数据授权方式是什么？这决定是否需要会员本人登录、短信验证或仅供内部员工使用。

## 实施纪律

每一项实施均需单独编号与设计，明确路由、权限、数据库/Flyway、事务、隐私影响和专项回归；不得把上述多项合并为一次大改。涉及 Cloudflare 的网络、账号、密钥、生产部署或个人信息外发，必须在单独授权后进行。
