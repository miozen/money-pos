# SYS-FIX-4：超级管理员修改本人登录名实施契约

## 已确认问题

`sys_user.username` 既是登录标识，也是 JWT audience 与（可选）Token 缓存键的一部分。既有通用
`PUT /users` 同时在前端和服务层禁止改名；且其角色等级保护不允许最高等级用户修改自身。因此，不能通过解除
通用编辑字段来实现超级管理员改名。

当前运行配置使用无状态 `jwt` 策略，access 与 refresh 的最长有效期均为 30 天。改名后旧 JWT 虽会因旧
用户名无法加载用户而在下一次受保护请求失败，但若旧用户名在有效期内被重新分配，旧 JWT 可能重新映射到新
用户。Redis 策略在未来启用时也必须同时清理旧用户名的 access/refresh 缓存键。

## 冻结范围

1. 新增仅限 `SUPER_ADMIN` 的“修改本人登录名”接口；当前用户 ID 来自认证上下文，不接收或信任前端用户 ID。
2. 不改变通用 `PUT /users` 的用户名不可编辑规则、角色等级规则、既有用户角色关系、密码、路由响应包装或
   登录请求格式。
3. 在同一数据库事务内：校验新登录名、保留旧登录名，并更新当前 `sys_user.username`。
4. 旧登录名按 access/refresh 中较长的有效期保留，期间不能被应用层新增账号复用；过期保留记录会在同名检查
   时清理。该保留保证旧 JWT 到期前不能重新映射到新账号。
5. 提交后清理可用的旧用户名 Token 缓存键；默认 JWT 策略保持无状态，旧用户名保留仍是其安全边界。
6. 成功响应后，前端只清除本地会话和 POS 记忆用户名，回到登录页；不依赖已改名身份再调用注销接口。

## 不在范围内

- 不修改 JWT claim 为 userId，不引入 Redis 运行依赖、全局签名密钥轮换、token 黑名单或多设备会话模型。
- 不开放其他用户改名，不变更角色/权限模型，不迁移历史审计字段中的用户名文本。
- 不改登录、刷新、注销、POS 收银或租户 API 的既有路径与请求结构。

## 验收条件

1. 非超级管理员不能调用该接口；调用者只能修改认证上下文中的自己。
2. 新名称与当前名称相同、已存在名称或仍在保留期的旧名称均失败。
3. 改名提交后旧用户名没有对应 `sys_user`，且保留记录到期时间不短于当前最长 token 有效期。
4. 旧用户名在保留期内不能通过用户新增流程重新使用；成功改名后的浏览器/POS 本地会话被清除。
5. 已启用 Redis TokenStrategy 时，旧用户名的 access/refresh 键会在事务提交后被删除；默认 JWT 策略保持兼容。
