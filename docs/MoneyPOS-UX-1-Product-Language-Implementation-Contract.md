# MoneyPOS UX-1 产品化可见语义实施契约

> 状态：本地实施与自动验证完成，待页面验收；确认日期：2026-10-26；适用分支：`dev`。

## 目标

将管理后台和操作提示中直接面向店主、收银员的工程术语，替换为可行动、易理解的产品语言；不改变任何业务规则、接口、权限、同步协议、交易数据或备份恢复流程。

## 已接受范围与顺序

1. **会员云端同步**：以“云端服务、同步密钥、会员检索密钥、同步队列、首次同步”替代 Worker、D1、HMAC、Base64、待发箱、回填、游标、快照与投递等实现术语。首次同步状态由内部状态码映射为中文；不再在普通页面显示会员游标。
2. **数据备份与恢复**：以“备份、恢复、恢复进度”替代核武级、物理级、底层引擎、控制台等措辞。保留 ZIP 限制、二次确认与输入“确认还原”的防误操作机制；不弱化覆盖本机资料的风险提示。
3. **顾客副屏设置**：以“顾客副屏、待机海报轮播、收款码展示”替代播控、终端状态机、驱动与资产映射。
4. **分散提示**：订单详情、利润审计、品牌策略和订单补打使用业务结果语义，不显示“底层快照”“部署”“指令”等内部措辞。

## 约束

- 云端地址、门店标识和两项密钥仍是必要的本机管理配置；仅变更它们的显示名称与提示语。
- 后端日志仍可保留诊断细节；面向 UI 的备份恢复进度和失败提示不得回显 SQL、HTTP、密钥、数据库表或内部实现名称。
- 恢复失败提示不得错误暗示数据已恢复；现有恢复原子性与回滚逻辑保持不变。
- 不修改数据库迁移、API 路径、返回形状、WebSocket 协议、Cloudflare Worker、POS 结算、库存、会员资产或权限判断。

## 验收

1. 云端同步页面不再显示 Worker、D1、HMAC、Base64、待发箱、回填、游标、快照或投递等普通操作文案；现有眼睛显示/隐藏密钥、测试连接、立即同步和重新同步行为保持不变。
2. 备份恢复仍需要 ZIP 文件、确认弹窗和“确认还原”输入；恢复完成后仍提示重启；恢复进度使用产品语言。
3. 顾客副屏设置、订单详情、利润审计、品牌设置与订单补打的改动只改变可见文案。
4. 前端构建、Maven 打包、架构门禁及 `git diff --check` 通过。
