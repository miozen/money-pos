# MoneyPOS UX-1.2：POS 用户名下拉登录分析

> 分析与实施日期：2026-09-23；源码基线：`dev` / UX-1.1 已验收。UX-1.2 已按本文实现，不改动 POS 登录业务领域逻辑。

## 结论

POS 登录可直接复用 UX-1.1 的账号候选与既有密码认证：登录页在普通入口也展示“昵称（登录名）”账号下拉和密码输入，提交仍然是现有的 `{ username, password }` 到 `POST /auth/login`。不需要新表、新 token、新权限或新后端端点。

这只是**登录输入方式统一**，不是“收银员切换”功能。已登录 POS 的锁屏、挂单/购物车归属和交班行为仍属于 UX-6，不能借此改动混入。

## 已确认事实

| 范围 | 当前行为 | 对 UX-1.2 的含义 |
| --- | --- | --- |
| 普通 POS 登录 | `Login.vue` 在非 `entry=admin` 时使用可输入的用户名输入框，成功后进入 `/pos`。 | 改成下拉，不改变成功后的路由。 |
| 后台登录 | `entry=admin` 已加载 `GET /auth/login-candidates`，显示启用账号的昵称，value 为 username。 | 将候选加载条件从“仅后台”扩大为“所有登录入口”。 |
| 认证 | `POST /auth/login` 使用 username/password 与既有 BCrypt、enabled 校验。 | 下拉仅帮助选择账号，绝不是认证或权限判断。 |
| 候选接口 | 仅默认租户、启用账号、最小字段；无缓存；仅 loopback。 | 可安全复用，不扩展匿名暴露面。浏览器开发模式经 Vite 本地代理访问，服务端看到的是本机来源。 |
| 会话 | token 位于 `sessionStorage`，普通登录会保存 `vanapos_remember_username` 到 localStorage。 | POS 关闭后仍需密码；下拉可保留“上次账号”作为默认选项，但不保存密码。 |
| 路由 | 无 token 访问 `/pos` 会被守卫导向 `/login?redirect=/pos`；普通登录目前固定回 `/pos`。 | 无需新增路由参数或 redirect 协议。 |

## 推荐交互

1. 打开 POS 或因无 token 被导向登录页时，加载候选列表并显示“请选择收银员”。
2. 候选项显示 `displayName`，值始终为不可变的 `username`；建议标签为“昵称（登录名）”，以免两个相同昵称无法区分。
3. 若 localStorage 有上次成功 POS 用户名且该用户仍在候选中，预选它并把焦点放在密码框；否则焦点停在下拉。
4. 密码输入、登录按钮、错误提示和登录协议维持现状。密码错误或账号被停用时不得进入 POS。
5. 候选加载失败时，禁用登录并提示“无法获取本机账号列表，请确认后台服务正常运行”；不回退为手输用户名，也不使用缓存列表。
6. 开发环境快捷登录标签保留为开发便利入口，点击后只填充表单；生产构建不显示。

## 实现边界

`Login.vue` 将以一个明确的 `isCandidateLogin`（普通 POS 或 admin）统一控制候选加载与 `<el-select>` 渲染；`entry=admin` 只继续负责登录后跳转 `/dashboard` 和不记住账号。普通 POS 继续登录后进入 `/pos`，可以保留上次账号提示。

不修改以下内容：

- `SysAuthController`、候选端点、数据库/Flyway、RBAC 和 token 协议；
- POS 订单、购物车、会员、挂单、交接班及 `create_by`；
- token 过期后的 axios “输入当前账号密码解锁”弹窗（它属于会话恢复体验，应单独决定是否也改为下拉）；
- 后台窗口隔离和关闭后重新登录规则。

## 实施结果

`Login.vue` 现始终使用候选账号下拉：后台仍显示“请选择后台账号”，POS 显示“请选择收银员”。候选标签在昵称与登录名不同时显示为“昵称（登录名）”，避免同名人员无法分辨。普通 POS 登录会在上次账号仍处于候选列表时预选该账号并聚焦密码框；否则聚焦账号下拉。候选接口失败时登录保持禁用，不退回手输账号。
